# Code Snippet Library development

This is an offline Windows desktop app with separate Java, Python, C#, C++, C, SQL, TypeScript, JavaScript, Go, Kotlin and COBOL sections, not a hosted service. Keep runtime assets bundled. Do not add accounts, telemetry, network APIs, a database, snippet execution, or a general frontend filesystem/shell interface. Development verification scripts are separate from app runtime.

The public app name is **Code Snippet Library**. Keep its header, document/window titles, installer and executable names consistent. Retain legacy `dev.javasnippets.library` and the Documents\Java Snippet Library storage path for upgrade compatibility; do not rename or reseed users' data as part of branding changes.

## Architecture and conventions

- TypeScript strict mode; React function components and hooks; meaningful typed interfaces in `src/models`.
- UI orchestration lives in `src/App.tsx`. Extract new substantial UI sections into `src/components`; hooks go in `src/hooks`.
- `services/markdown.ts` owns metadata validation, Markdown parsing and serialization. Never assume pasted/imported content is valid. Treat code and notes as text. Shiki is the only trusted generated HTML.
- `models/languages.ts` owns language labels, imports and version comparisons. Missing `language` means Java; Python requires `language: python` and a quoted `pythonVersion` string. Keep IDs globally unique. Compare Python version components, never decimal numbers.
- C# uses `language: csharp`, quoted `csharpVersion` and quoted `dotnetVersion` (modern .NET 5+). Keep language syntax requirements distinct from the .NET target. C# frontmatter imports omit `using`/semicolons; `importLines()` formats namespace or static using directives. Add languages to the shared configuration for labels, extensions, symbols, versions and storage folders.
- C++ uses `language: cpp`, integer `cppVersion` (11, 14, 17, 20 or 23), and `cpp` fences. Its `imports` array holds `<header>` or quoted project-header tokens without `#include`. The viewer labels these Headers and copying prepends include directives. Load the bundled C++ grammar on demand; never use a CDN.
- `components/LanguageSections.tsx` switches the active section. Scope categories, tags, results, favorites/recent views and version filters to that section, preserve its selected category, and create snippets in its language.
- `search/search.ts` owns search weights and combined filters. Generate categories/tags from metadata. Java-version filtering means snippet minimum <= user's selected version.
- `services/storage.ts` switches between Tauri commands and a clearly labeled browser-local preview. Do not silently fall back from failed native storage to browser storage.
- Rust commands in `src-tauri/src/lib.rs` restrict access to the library and fixed configuration paths. Keep path traversal, symlink/reparse checks, file-size limits, duplicate ID validation, original-content conflict detection and atomic writes. Export destinations require the native save dialog.
- Favorites/history/preferences stay outside snippet content. First-run seeding must never overwrite user files or re-add deleted defaults on normal launches.
- Preserve the existing app identifier and Documents library path. Python defaults live in `DefaultPythonSnippets/` and are added to `Python/` with a separate `python-initialized-v1` upgrade marker. Keep legacy Java initialization unchanged. The browser preview has its own one-time Python migration. Both must preserve existing paths, IDs and edits.
- C# defaults live in `DefaultCSharpSnippets/` and are added to `CSharp/` with `csharp-initialized-v1`. Rust shares the safe upgrade helper while keeping each language's marker independent. The browser preview also has independent markers. Never reseed older sections when adding a new language.
- C++ defaults live in `DefaultCppSnippets/` and are added to `Cpp/` with `cpp-initialized-v1`. Both native and browser upgrades preserve existing paths/IDs/edits/deletions and keep earlier language markers intact.
- SQL defaults live in `DefaultSqlSnippets/` and are added to `SQL/` with `sql-initialized-v1` (browser: `jsl.sql-initialized.v1`). SQL requires `sqlDialect`, `sqlKind` and quoted `sqlVersion`; SQL Server uses release years. Only compare database versions within a selected dialect. SQLite cannot contain procedures; PostgreSQL procedures require 11+, MySQL 5+. Use `sql` fences, optional `sql primary`, and notes for schema/setup; SQL has no imports. Keep its bundled grammar local and lazy.
- TypeScript uses `language: typescript`, quoted `typescriptVersion`, and `typescript` fences. Imports are complete single-line import statements without semicolons; copy adds semicolons. Document runtime/target and local module/package requirements separately from compiler version. Its grammar is bundled and lazy. Defaults in `DefaultTypeScriptSnippets/` seed `TypeScript/` once with `typescript-initialized-v1` (browser: `jsl.typescript-initialized.v1`), preserving older content and markers.
- Snippets are raw UTF-8 `.md` files. Preserve entire Markdown on edit/import/export and indentation on copy. Support multiple blocks and exactly one optional primary fence.
- Themes use CSS variables. Keep keyboard interactions, modal focus, accessible labels, visible focus, reduced motion and both themes working.
- Avoid broad refactors unrelated to the task. Do not regenerate defaults when editing an individual example. `scripts/seed-snippets.mjs` documents original generation; rerunning it overwrites bundled source examples.

## Required verification

Run `npm test` and `npm run build` for frontend changes. Run `npm run test:ui` for interaction changes (uses Edge). Run `cargo test --manifest-path src-tauri/Cargo.toml` for native changes, or `powershell -ExecutionPolicy Bypass -File scripts/desktop.ps1 test` for the ignored local Rust toolchain. Rustfmt changed Rust files. Do not claim native behavior was checked by browser tests.

For Java example changes run `node scripts/verify-java.mjs` with JDK 21+; add context variables there for new examples. This is compile-time verification at the declared minimum release, not integration testing against external services. Label all third-party dependencies and checked exceptions accurately.

For Python example changes run `npm run verify:python` with Python 3.9+ (`py -3` or `PYTHON` set to an interpreter path). This development-only script uses temporary fixtures and assertions. Add assertions for new examples; do not claim old Python runtimes were tested just because an AST feature-version check passed.

For C# example changes run `npm run verify:csharp` with a C# 12-capable .NET SDK and the .NET 8 targeting pack/runtime. The development script compiles each example at its declared language version and .NET target, then runs assertions with isolated fixtures. Add an assertion for every new example. Do not add runtime snippet execution to the app.

For C++ example changes run `npm run verify:cpp` on Windows with Visual Studio C++ Build Tools. The local helper sets the compiler environment; the development script builds examples in their declared standard modes and runs behavior assertions with isolated fixtures. The bundled collection uses C++14/17/20; MSVC has no exact C++11 mode. Add an assertion for every new example and keep compiler checks separate from app runtime.

`npm run installer` creates NSIS output under `src-tauri/target/release/bundle/nsis/`. The first package build requires network downloads. Don't install Rust globally if the existing `.tools/` toolchain is suitable. Never check in `.tools`, `node_modules`, `dist`, `target` or generated test artifacts. Commit both npm and Cargo lockfiles with dependency changes.

For SQL example changes run `npm run verify:sql` with Python, a .NET SDK/.NET 8 targeting pack/runtime, and the ScriptDom DLL from SSMS 21 (or `SQL_SCRIPTDOM`). Add query result assertions to the isolated SQLite fixtures. SQL Server procedure checks parse syntax with TSql140Parser; they do not execute procedures or verify schemas, permissions or transactions. Do not connect to a user's database for verification or add SQL execution to app runtime.

For TypeScript example changes run `npm run verify:typescript`. It compiles trusted defaults using the installed compiler, strict mode and ES2020, then runs behavior assertions with isolated fixtures. Add assertions per example. Report the actual compiler tested; declared older baselines are not separately verified by this script. Keep compilation/execution confined to development tooling.

C uses `language: c`, integer `cVersion` (89, 99, 11, 17, 23), and `c` fences. C89/C90 uses 89. Compare standards chronologically, never numerically. Headers use the C++ header-token format and Copy with headers. Defaults in `DefaultCSnippets/` seed `C/` with `c-initialized-v1` (browser `jsl.c-initialized.v1`). Preserve earlier content and markers. Its grammar stays bundled and lazy.

For C examples run `npm run verify:c` with Visual Studio C++ Build Tools. It compiles trusted complete programs in C mode with `/TC`, declared C11/C17 standard, warnings as errors, and output/file assertions in isolated fixtures. Add checks per example; do not claim C89/C99/C23 compiler verification. Document ownership, errors, bounds, and runtime/file assumptions. Do not add runtime compilation or execution to the app.

JavaScript uses `language: javascript`, integer `javascriptVersion` (ECMAScript year 2015–2099), `javascript` fences and an optional primary marker. Imports are complete single-line statements without semicolons; TypeScript type imports are invalid. Keep runtime/host/module requirements distinct from ECMAScript year. Bundle its grammar locally and load it lazily. `DefaultJavaScriptSnippets/` seeds `JavaScript/` once with `javascript-initialized-v1` (browser `jsl.javascript-initialized.v1`), preserving earlier content and markers.

For JavaScript example changes run `npm run verify:javascript`. This development-only verifier checks trusted defaults with Node syntax checks and behavior assertions using isolated module fixtures. Add checks per example, including failure cases where appropriate. Report the actual Node version tested; do not claim minimum-version or browser verification from a modern Node run. Do not run user/imported snippets or resolve their imports in app runtime.

Go uses `language: go`, quoted `goVersion` (1.minor), `go` fences and an optional primary marker. Compare minor components numerically. Import values are unquoted package paths (no aliases/import keyword); Copy with imports places a grouped block after a standalone package declaration, or prepends it to a declaration fragment. Document any aliased imports in code, without duplicating metadata imports. Keep the grammar bundled and lazy. `DefaultGoSnippets/` seeds `Go/` once with `go-initialized-v1` (browser `jsl.go-initialized.v1`), preserving older content and markers.

For Go examples run `npm run verify:go` with `GO_BINARY`, the project-local `.tools/go/bin/go.exe`, or Go on PATH. It compiles trusted defaults with each declared `-lang=go1.x`, then checks output/files using isolated fixtures and caches with module/toolchain downloads, telemetry and CGO disabled. Report the actual compiler and distinguish language-mode checks from older standard-library/toolchain testing. Add assertions per example. Do not compile/run user snippets or add a Go dependency to app runtime.

Kotlin uses `language: kotlin`, quoted `kotlinVersion` (major.minor), integer `jvmTarget` (8, 11, 17 or 21), `kotlin` fences and optional primary markers. Kotlin version filters are separate from the displayed JVM bytecode target. Imports are qualified names with optional as aliases or wildcard suffixes, without import/semicolons. Copy imports after a standalone package declaration, or prepend them to package-less code. Keep its grammar bundled and lazy. `DefaultKotlinSnippets/` seeds `Kotlin/` once with `kotlin-initialized-v1` (browser `jsl.kotlin-initialized.v1`), preserving older content and markers.

For Kotlin examples run `npm run verify:kotlin` using `.tools/kotlinc` or `KOTLIN_HOME`, and Java via `JAVA_BINARY`/`JAVA_HOME` or a suitable local JDK. It compiles trusted defaults at declared language/API versions and JVM targets, then checks output/files in isolated fixtures. Report actual compiler/JVM versions; old language/API modes and bytecode targets do not prove old-runtime compatibility. Keep JVM-only and external dependencies documented, and keep compilation/execution out of the application.

COBOL uses `language: cobol`, integer `cobolVersion` (1985/2002/2014/2023), `cobolFormat` (fixed/free), and `cobol` fences. Free format requires 2002+. Preserve fixed-format leading spaces/columns on edit/copy/import/export. Keep COPY clauses in source and requirements in notes; metadata imports are invalid and the Imports UI is hidden. `DefaultCobolSnippets/` seeds `COBOL/` once with `cobol-initialized-v1` (browser `jsl.cobol-initialized.v1`), preserving previous content and markers. Its basic project-owned grammar in `src/languages/cobol.ts` is loaded lazily by Shiki, the sole HTML renderer.

Run `npm run verify:cobol` for COBOL examples using a portable GnuCOBOL distribution under `.tools/cobol` or `COBOL_HOME`, with its C toolchain/runtime dependencies. Compile at declared standard/source-format modes with output and isolated file assertions. Distinguish GnuCOBOL checks from mainframe/vendor/encoding compatibility. COBOL 1985 examples use standard display-and-stop error branches without promising nonzero process status. The compiler/runtime stay out of app runtime. Test grammar escaping and both themes when changing the COBOL grammar.

Hello World templates live separately in `StarterSnippets/`, arranged by their actual library paths (`Starters/` for Java, `<language folder>/Starters/` for others). Add them once with `starters-initialized-v1` (browser `jsl.starters-initialized.v1`) using the safe upgrade helper; never reseed older examples or deleted starters. The category is Starter Templates/Hello World. Use as template opens a new unsaved copy with a fresh identity via `services/markdown.ts::templateDraft`; preserve the complete body, notes and other metadata. Capture the editor's initial content once so template IDs and dirty-state checks stay stable across renders.

Run `npm run verify:starters` when changing the complete templates. It compiles/runs each trusted starter with existing local toolchains and asserts the exact greeting; SQL uses isolated in-memory SQLite. C/C++ require the existing Visual Studio tools, Kotlin/Go/GnuCOBOL use their local toolchains, and Java/Python/.NET/TypeScript use the installed tools. Run the relevant existing language verifiers as well. Keep all runtime compilation/execution out of the app.
